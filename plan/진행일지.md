## AI가 먼저 정한 것 (CEO 확인 대기 — 되돌리면 여기에 표시)

- A1 · Noto Sans KR 설치본 굵기: Regular·Bold 두 가지(할 일 #42). 근거: 양식 문서는 보통·굵게만 쓰는 경우가 대부분이고, 크기를 줄인다.
- A2 · 엔진 포크 방식: 지금은 로컬 포크(E:\OCTO\work\rhwp, E:\OCTO\work\wordcraft, 각자 docsocto 브랜치)를 DocsOcto 작업공간이 경로로 참조한다. 저장소에 소스를 넣는 방식(벤더링 또는 GitHub 포크)은 공개 준비(M5) 때 정한다. 근거: GitHub에 포크 저장소를 만드는 것은 외부 게시라 승인 없이 하지 않는다.
- A3 · 보존 저장 방식(M1 첫 작업, 9절 대책의 구현): 엔진에 상관없는 "3자 병합"으로 한다.
  O=원본 패키지, B0=엔진이 고치지 않고 저장한 것, B1=엔진이 고쳐서 저장한 것.
  · 항목(part)이 B0와 B1에서 같으면 → 원본 O의 항목을 그대로 쓴다.
  · 다르면 → 문단(HWPX hp:p / docx w:p·w:tbl) 단위로 B0와 B1을 맞대어, 바뀐 문단만 B1에서 가져와 원본 O의 같은 자리에 끼운다. 정렬이 안 맞으면 그 항목만 B1 전체를 쓴다(보고서에 남김).
  · 엔진이 빠뜨린 항목(그림 등)은 원본에서 시작하므로 저절로 남는다.
  · 끼운 문단이 참조하는 id(글자 모양 id, 관계 r:id, 스타일 id)는 원본 쪽 id로 다시 맞춘다. 맞출 수 없으면 정의를 원본 header/styles에 덧붙인다.
- A4 · docx 시험 문서는 10종까지 채운다(7절의 30종은 M1 회귀 묶음에서 채운다).
- A6 · 셀 쓰기 기본 서식: 양식 칸에 써 넣은 글자는 그 칸의 원래 서식을 그대로 쓴다(rhwp set-cell --keep-style 상당). rhwp 기본값(검정·비굵게로 덮기, #3391)은 선택 옵션으로 둔다. 근거: 기획서 7절 '손대지 않은 부분 차이 0', M0에서 써 넣은 글자가 한글에서 다른 모양으로 보임.
- A7 · 글꼴 탐색 경로: OS 글꼴 폴더 + DocsOcto 사용자 글꼴 폴더 + (PC에 있으면) 한컴오피스 글꼴 폴더(…\Hnc\…\Shared\TTF). 모두에 없을 때만 Noto Sans KR로 그린다. 근거: 7절 '쓰인 글꼴이 PC에 있으면 그대로 쓴다' — 한컴오피스가 설치한 글꼴도 PC에 있는 글꼴이다.
- A8 · M1-2 결론: '써 넣은 글자가 굵게'는 버그가 아니라 원래 칸의 글자 모양(앞은 보통, 뒤는 굵게)을 위치대로 이어받은 것. DocsOcto 셀 쓰기(M1-5)는 칸 전체를 바꿀 때 첫 글자 모양 하나로 통일한다.
- A9 · 글꼴 대체 순서: 결정 #13(없는 글꼴은 Noto Sans KR)과 7절 첫째 기준(한글 PDF와 같음)이 부딪친다. 지금은 첫째 기준을 앞세워 rhwp의 '한글 흉내' 대체 순서(맑은 고딕·함초롬 먼저)를 두고, Noto Sans KR은 대체 글꼴이 하나도 없을 때의 마지막 글꼴(설치본 포함)로 둔다. ★CEO 확인 필요(#13과 어긋남).
- A10 · ohwp 표 번호: 본문 최상위 표만 0부터 센다(rhwp export-tables와 같은 번호). 중첩 표 편집은 M1 뒤로.
- A11 · 쪽 그림(render.page)은 SVG·PDF로 낸다. PNG는 rhwp native-skia(Skia 라이브러리) 기능이 필요해 뒤로 미룬다.
- A12 · 셀 쓰기가 칸 서식을 이어받으므로, 원래 흰 글씨·숨김 같은 칸(예: '※삭제 후 제출' 안내 칸)에 쓰면 인쇄물에 안 보일 수 있다. 칸을 고르는 일은 M3 질문 칸 추출에서 다룬다.
- A13 · 공통 명령의 위치 규칙: para는 본문 문단 번호(HWPX는 구역 안 문단, docx는 본문 블록 — 표도 한 칸, md·txt는 줄), offset 등은 글자(유니코드 문자) 단위, table은 본문 최상위 표 번호, row·col은 격자 좌표. 공통 명령 23개, 목록에 없는 명령은 그 형식 엔진 명령으로 그대로 넘긴다.
- A14 · md·txt: 인코딩은 BOM → UTF-8 → 아니면 CP949(EUC-KR)로 읽고 같은 인코딩으로 쓴다. 줄마다 원래 줄바꿈을 지킨다. md의 굵게·기울임은 ** · * 로 감싼다(밑줄·정렬은 없음).
- A15 · 설정 파일: %APPDATA%\com.flyocto\flyocto\Docs\settings.json(default_format, language). 처음 실행 시 기본 형식을 안 골랐으면 새 문서 만들기에서 init을 안내한다. 언어는 설정 → 없으면 OS 언어(한국어면 ko, 아니면 en).
- A16 · MCP 도구 6개: list_commands, open, run, save, close, inspect. save는 원본을 덮어쓰지 않는다(overwrite=true일 때만).
- A5 · GitHub 올리기: 밤사이에는 로컬 커밋만 한다. 외부 게시는 승인 뒤(규칙). CEO가 아침에 "올려"라고 하면 한 번에 올린다.

AI가 먼저 정한 것(M3)
- A17 · 답을 쓰는 것은 DocsOcto 안의 AI가 아니라 MCP로 붙은 AI(Claude·Codex)다. DocsOcto는 칸 뽑기·자료 읽기·채우기·확인 도구만 준다(5절 '엔진은 네트워크를 쓰지 않는다').
- A18 · 칸 뽑기(form.slots): 표의 빈 칸(또는 '※…'·'(예시)'·'(공란)' 같은 안내문만 든 칸)을 입력 칸으로 보고, 같은 행 왼쪽 글자 칸 → 없으면 같은 열 위쪽 글자 칸을 라벨로 붙인다. 표 바로 앞 문단을 표 제목으로 붙인다. '□ 보기' 묶음은 고르기 칸, 누름틀은 그대로 칸으로 낸다. 칸 id: t<표>r<행>c<열>, f:<누름틀 이름>, t<표>r<행>c<열>:□<보기>.
- A19 · 채우기(form.fill): {answers:[{id, value}]} 한 번에. 고르기 칸은 □를 ■로 바꾼다. 채운 뒤 칸 넘침(글자가 칸보다 넓음)을 보고한다.
- A20 · 참고 자료 읽기(docsocto read): hwpx·hwp·docx·md·txt·pptx·xlsx·pdf를 글자로 뽑는다. 숫자의 출처를 밝히도록 위치(쪽·시트·셀·슬라이드)를 함께 낸다(9절 'AI가 숫자를 지어냄' 대책).
- A21 · 시나리오: 시료 17_서초구_중소기업육성기금_융자신청서(정책자금 융자 신청서)를 양식으로, 가상의 회사 자료 3종(회사소개 docx, 재무제표 xlsx, 사업계획 pdf)을 만들어 쓴다. 실제 회사·개인 정보는 쓰지 않는다.
- A22 · MCP 연결: Claude Code는 저장소의 .mcp.json(프로젝트 범위), Codex는 실행할 때 -c 설정으로 붙인다. 사용자 전역 설정은 건드리지 않는다.
- A23 · '사람 수정 시간 절반' 기준은 사람이 재야 한다 — AI는 채운 결과·걸린 시간·남은 빈칸을 보고서로 내고, 사람 측정은 CEO 확인 항목으로 남긴다.
- A24 · 칸 넘침은 글자 수로 짐작하지 않고 렌더한 쪽에서 재야 맞다 — form.fill에서 빼고 M3-4 form.check(렌더 뒤 넘침·빈칸 보고)에서 한다.
