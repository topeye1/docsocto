# DocsOcto 기획서

상태: 승인 (CEO 2026-10-25) — M0 시작 2026-10-25
작성일: 2026-10-25
출처: 마이프로젝트 방 "동영상편집" 대화와 결정 #5·#6·#8·#9

## 1. 배경과 목표

지금 불편한 점
- 정부·공공 업무(정책자금 신청, 보고, 공문)는 HWP/HWPX로 내야 한다. 민간은 docx를 쓴다. 두 형식이 서로 잘 이어지지 않는다.
- AI가 HWP를 직접 고치지 못한다. 그래서 AI로 md 초안을 만든 뒤 사람이 한글에 붙여 넣고 서식을 다시 잡는다.
- 기존 자료(pptx·docx·xlsx)가 있어도 기관마다 양식과 질문이 달라서, 매번 다시 다듬어 칸마다 입력한다.

목표
- AI와 사람이 docx와 HWPX를 한 앱에서 같은 명령으로 다룬다. 문서는 원래 형식 그대로 고친다(결정 #8).
- DocsOcto는 '기본 텍스트 편집기'다. 문서(docx·HWPX)뿐 아니라 일반 텍스트 파일(md·txt)도 같은 앱에서 편집한다(Docs 방 결정 #1).
- 성공하면 "회사 자료와 기관 양식을 넣으면, 양식 서식 그대로 채워진 HWPX 초안이 나온다."

사업 위치
- 수익원이 아니다. 무료로 풀고 flyocto를 알리는 매개체로 쓴다(결정 #6).
- HWP 엔진(가칭 ohwp)은 오픈소스로 공개한다(결정 #5).

## 2. 대상 사용자와 시나리오

대상
- 1차: 우리 회사 내부(정책자금·지원사업 신청, 공공기관 제출 문서)
- 2차: 공공 업무가 많은 중소기업과 기관 실무자(무료 배포)

시나리오
1. 정책자금 신청: 기관 HWPX 양식과 회사 소개서(pptx)·사업계획서(docx)·재무표(xlsx)를 넣고 "이 양식 채워 줘"라고 지시한다. 그러면 질문마다 답이 양식의 칸에 들어간 HWPX가 나오고, 사람은 검토만 한다.
2. 부분 수정: 이미 낸 HWPX의 표에서 금액 하나, 문장 하나를 고치라고 말로 지시한다. 그러면 그 객체만 바뀌고 나머지 서식은 원본과 똑같이 남는다.
3. 형식 변환: 사람이 "이 HWPX를 docx로도 만들어 줘"라고 요청한다. 그러면 docx 표준을 따른 새 파일과 함께, 옮기지 못한 요소의 목록이 나온다.
4. 원격 지시: 폰에서 마이프로젝트 방으로 지시하면 사무실 PC(호스트)가 처리하고, 결과는 폴더 공유로 받는다. 문서는 사설망 밖으로 나가지 않는다.

## 3. 기능 목록 (우선순위 순)

| 순위 | 기능 | 설명 | 필수/선택 |
|---|---|---|---|
| 1 | HWPX 직접 편집 엔진(ohwp) | rhwp를 기반으로 문단 삽입·삭제, 글자·문단 서식, 표 구조(행·열·병합·테두리), 셀·누름틀 입력, 저장 | 필수 |
| 2 | 명령 체계 | WordCraft처럼 모든 동작을 "명령 id + 매개변수"로 만든다. list_commands·inspect·render 제공 | 필수 |
| 3 | CLI + MCP | Claude·Codex 등이 로컬에서 바로 호출. 형식에 따라 엔진을 자동으로 고른다 | 필수 |
| 4 | docx 편집 | WordCraft 엔진으로 처리하고, 같은 명령 이름으로 맞춘다 | 필수 |
| 4a | 텍스트 파일 편집(md·txt) | 변환 없이 텍스트 그대로 열고 고쳐 저장한다. 원래 인코딩·줄바꿈을 유지하고, 문단·줄 단위 명령은 docx·HWPX와 같은 이름을 쓴다(Docs 방 결정 #1) | 필수 |
| 5 | 기본 형식 설정 | 처음 실행할 때 HWPX/docx 중 기본값을 고른다. 선택지는 이 둘뿐이고 md·txt는 넣지 않는다(CEO 결정 2026-10-25). 새 문서와 변환 대상이 이 값을 따른다(결정 #9) | 필수 |
| 5a | 글꼴 자동 준비 | 문서를 열 때 없는 글꼴은 무료면 내려받고, 아니면 대체 글꼴로 그린다. 문서 안 글꼴 이름은 바꾸지 않는다(Docs 방 결정, 7절 글꼴 정책) | 필수 |
| 6 | 렌더 확인 | 쪽 단위로 SVG/PNG를 출력해서 AI가 넘침·깨짐을 스스로 확인 | 필수 |
| 7 | 양식 채우기 흐름 | 양식의 질문·칸 추출 → 자료 읽기 → 답 작성 → 채우기 → 검토 표시 | 필수 |
| 8 | 요청형 변환 | docx↔HWPX. 사람이 요청할 때만 하고, 받는 쪽 표준을 따른다. 결과는 눈으로 보이는 것이 원본과 같아야 한다(7절 호환 기준 5). 변경 추적 같은 보이지 않는 기능은 옮기지 않아도 되고, 옮기지 못한 것은 변환 보고서에 적는다(결정 #8) | 필수 |
| 9 | flyocto 연동 | 마이프로젝트 방 지시, 폴더 공유 결과, 백그라운드 작업 알림 | 필수 |
| 10 | 데스크톱 편집 화면 | 사람이 직접 고치는 GUI(WordCraft의 egui 화면 기반) | 선택(2차) |
| 11 | HWP 5.0 바이너리 편집 저장 | v1에서는 열기와 HWPX 변환만 하고, 편집 저장은 rhwp 기존 범위 안에서만 지원 | 선택 |

## 4. 화면·사용 흐름

지원 OS: Windows·macOS·Linux(CEO 지시 2026-10-25). 엔진(rhwp·WordCraft)이 모두 Rust라 세 OS에서 같은 코드로 빌드한다. OS마다 다른 부분(설치된 글꼴 찾기, 글꼴 내려받기 위치, 설정 파일 위치, 설치 패키지)만 따로 만든다.

설치·설정·산출물 위치 (OCTO세상 방 결정 #3·#4, 2026-10-25)
- 설치: 항상 C:\Program Files\Flyocto\Docs에 설치한다. flyocto가 없는 PC에서 DocsOcto만 설치해도 같은 위치다(CEO 지시 2026-10-25). macOS·Linux도 같은 원칙으로 Flyocto/Docs 아래에 설치한다(정확한 경로는 M5에서 확정).
- 사용자별 설정: flyocto가 쓰는 사용자 설정 위치를 그대로 쓴다(Windows: %APPDATA%\com.flyocto\flyocto 아래 Docs). flyocto가 없어도 같은 위치를 만들어 쓴다. 내려받은 글꼴, 사용자 글꼴 폴더도 이 아래에 둔다.
- 산출물(렌더 이미지·변환 보고서·편집 결과 사본): 방 산출물 규칙을 따른다 — 방 폴더\문서\<종류>\<YYMMDD>_<제목>.<확장자>. 원본 문서를 고칠 때는 원래 자리에 저장한다.
모든 메뉴·화면 문구·CLI 도움말·오류 메시지는 한글을 기본 언어로 한다(CEO 지시 2026-10-25). 지원 언어는 한글·영어 둘이다. OS 언어가 한국어가 아니면 처음 실행할 때 영어로 나오고, 설정에서 언제든 한글·영어를 바꿀 수 있다(CEO 지시 2026-10-25).

v1은 대화와 CLI/MCP가 중심이다. 편집 화면(GUI)은 2차로 미룬다(CEO가 AI 판단에 맡김 2026-10-25 — 판정이 PDF 비교라 v1에 GUI가 필요 없고, 개발 인원이 1명이라 범위를 줄인다).

CLI 예시
```
docsocto init --default hwpx            # 기본 형식 고르기 (처음 1회)
docsocto inspect 신청서.hwpx              # 구조·질문 칸·누름틀 목록
docsocto run 신청서.hwpx table.setCell '{"table":2,"row":3,"col":2,"text":"1,200,000,000"}'
docsocto render 신청서.hwpx --page 3     # 쪽 그림으로 확인
docsocto convert 신청서.hwpx --to docx   # 사람이 요청할 때만, 변환 보고서 함께 출력
docsocto mcp                             # AI 연결
```

대화 흐름(마이프로젝트 방)
양식과 자료를 폴더 공유에 넣는다 → "채워 줘"라고 지시한다 → AI가 MCP로 채우고 렌더해서 확인한다 → 쪽별 미리보기와 결과 링크를 받는다 → 사람이 "3번 답 줄여"처럼 말로 고친다 → 사람이 최종 검토하고 제출한다.

## 5. 데이터

- 입력: HWPX·HWP·docx 문서, md·txt 텍스트 파일, 기관 양식, 참고 자료(pptx·docx·xlsx·pdf). 위치는 사용자 기기 또는 폴더 공유.
- 저장: 원본은 덮어쓰지 않는다. 기본값은 `<원본이름>_수정.hwpx`처럼 새 파일로 저장한다. 덮어쓰기는 사람이 명시할 때만 한다.
- 출력: 편집된 문서(원래 형식), 쪽 렌더 이미지, 변환 보고서(md), 편집 전후 비교(rhwp ir_diff 기반).
- 외부 전송: 엔진은 네트워크를 쓰지 않는다. AI 서비스로 가는 것은 명령과 추출한 텍스트뿐이다(이 범위는 사용자에게 알린다).

## 6. 제외 범위 — 이번(v1)에 안 만드는 것

- 데스크톱 편집 화면(GUI) — 2차
- 모바일 앱, 웹 편집기
- 클라우드 서버 방식의 문서 처리(로컬 전용)
- 실시간 공동 편집, 변경 내용 추적
- 한컴오피스와 같은 수준의 모든 조판 기능(글자 겹치기, 각주 세부 등 특수 기능은 "보존만" 하고 편집하지 않음)
- 유료 기능·과금
- 문서 제출 자체(기관 사이트 업로드)는 사람이 한다
- md·txt를 docx·HWPX로 바꾸는 변환 — 넣지 않는다. 어떤 형식으로 저장할지는 사용자가 저장할 때 정할 일이다(CEO 결정 2026-10-25)

## 7. 완료 기준

호환 기준 (CEO 지시 2026-10-25 — 제품의 첫째 기준)
1. DocsOcto에서 저장한 docx가 MS Word에서 깨지지 않는다.
2. MS Word에서 저장한 docx가 DocsOcto에서 깨지지 않는다.
3. DocsOcto에서 저장한 HWPX가 한글 오피스에서 깨지지 않는다.
4. 한글 오피스에서 저장한 HWPX가 DocsOcto에서 깨지지 않는다.
5. DocsOcto에서 docx→HWPX, HWPX→docx로 저장할 수 있고, 결과가 깨지지 않는다. 변경 추적 같은 복잡한 기능은 없어도 되고, 눈으로 보이는 것만 같으면 된다.

"깨지지 않는다"의 판정 (Docs 방 결정 #5)
- 열기: 오류나 "복구할까요" 창 없이 열린다.
- 비교: Word·한글에서 내보낸 PDF와 DocsOcto에서 내보낸 PDF를 쪽마다 그림으로 겹쳐 비교한다. 쪽 수·글자 위치·표(행·열·병합·테두리)·그림·머리말/꼬리말·쪽 번호가 같으면 통과. 한두 글자 줄바꿈 차이는 허용, 쪽 넘김·표·그림 밀림은 실패.
- 양쪽 PC에 같은 글꼴이 설치된 상태에서 비교한다(시험 PC에 시험 문서가 쓰는 글꼴을 맞춰 둔다).
- 시험 문서: 기관 HWPX 양식 30종 + 실무 docx 30종(표·그림·머리말이 있는 것 위주).
- 이 방식이면 호환 기준 2·4도 DocsOcto의 PDF로 확인하므로 v1에 GUI가 없어도 된다.

글꼴 정책 (Docs 방 결정, CEO 지시 2026-10-25 — "우리가 글꼴까지 신경 쓰지 않는다")
- 표준 글꼴은 Noto Sans KR 하나로 하고 설치본에 기본으로 넣는다(CEO 결정 2026-10-25). OFL 무료라 함께 배포해도 된다. 한글·영문·한자를 모두 갖고 있다.
  · 설치본에 들어 있으므로 인터넷이 없어도 표준 글꼴로 그릴 수 있다.
  · 설치본 크기가 글꼴만큼 늘어난다(굵기 수에 따라 수 MB~수십 MB — M0에서 넣을 굵기 확정).
- 문서의 글꼴 이름은 바꾸지 않고 그대로 둔다.
- 문서를 열 때 쓰인 글꼴이 PC에 있으면 그대로 쓴다.
- 없으면 무료로 받을 수 있는 글꼴인지 보고 내려받아 쓴다(Google Fonts 등 공개 배포처).
- 무료로 받을 수 없는 글꼴(맑은 고딕·바탕·굴림처럼 OS에 딸린 것, 상용 글꼴)과 인터넷이 없어 못 받은 글꼴은 표준 글꼴 하나로 그리기만 하고 문서 안 이름은 그대로 둔다. 받는 사람이 그 글꼴을 가지고 있으면 원래 모양으로 보인다.
- 계열별·글자 폭별 대체 표는 두지 않는다. 대신 그린 글꼴이 있으면 열 때 목록(원래 글꼴 → 표준 글꼴)을 알린다.
- 사용자 글꼴 추가는 가장 편한 방식으로 한다(CEO 지시 2026-10-25, 결정 #7): OS에 글꼴을 평소처럼 설치하면 DocsOcto가 그대로 쓴다. 별도 설정은 없다. 설치 권한이 없으면 DocsOcto 사용자 글꼴 폴더에 파일을 넣기만 해도 인식한다.

## 9. 위험과 대책

| 위험 | 대책 |
|---|---|
| HWPX 저장 후 한컴오피스에서 서식이 달라짐 | M0에서 먼저 확인. 손대지 않은 부분은 원본 XML을 그대로 유지하는 보존 방식으로 저장 |
| rhwp·WordCraft 둘 다 알파 단계라 기능·완성도가 부족함 | 원본을 기다리지 않는다. 시작 시점 버전으로 포크하고, 우리에게 필요한 기능은 직접 만들어 완성도를 올린다. 원본의 좋은 수정은 골라서 가져오고, 원본에 돌려주는 기여는 선택 사항으로 한다 |
| 상표: "한글"·"HWP"(한컴), "ArtCraft"(ArtCraft 팀), "DocsOcto" 사용 가능 여부 | 제품 이름에 HWP를 넣지 않음. ArtCraft 이름·로고 제거. 공개 전 상표 검색 |
| HWP 형식 공개 문서의 고지 조건 | 공개 전 원문 확인 후 고지 문구 반영 |
| AI가 숫자·사실을 지어냄 | 숫자는 참고 자료에서만 가져오게 하고 출처를 표시. 사람의 최종 검토 단계 필수 |
| 무료 배포 후 문의·버그 대응 부담 | 지원 범위를 이슈 게시판으로 한정하고 공개 전에 명시 |

## 10. 기술 바탕 (확인한 사실)

- rhwp: Rust + WASM, MIT. HWP 5.0·HWPX 파싱·저장, CLI(info·dump·export-svg·export-pdf), MCP 내장(읽기·검색·구조·표 추출, 누름틀 채우기, 셀 쓰기, 문구 치환, ir_diff). 문단 삽입·서식은 웹 에디터에만 있고 MCP에는 열려 있지 않음. 최신 v0.8.7.
- WordCraft: 순수 Rust(egui, WASM), MIT 또는 Apache-2.0. ArtCraft 상표는 포크에서 제거해야 함. docx 읽기·쓰기, 명령 422개, CLI·MCP. 알파 단계(자체 추정 실사용 준비도 약 60%).
- 두 엔진이 모두 Rust여서 한 저장소·한 빌드 체계로 묶기 쉽다.
- 저장소: 원격 github.com/topeye1/docsocto(공개, main), 개발용 로컬 저장소 E:\OCTO\DOCS(CEO 지시 2026-10-25)
